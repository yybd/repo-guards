# ‏tools/ — חדר הבקרה

לא סקילים. אלה החלקים של grove שאדם מריץ: הרישום של איפה יושב כל פרויקט, הפריסה שהופכת
עריכה למשהו אמיתי, והפקודות ששומרות על הרשומות נאמנות למציאות.

*נספר מהדיסק ב‑2026-09-11: עשרה סקריפטים כאן, שבעה מעקות בפלאגין.*

## הסקריפטים, ועל איזו שאלה כל אחד עונה

| | |
|---|---|
| `deploy.py` | **"הפוך את מה שה‑repo מחזיק לאמיתי על המכונה הזו."** הגדרות מהרישום, אחר כך ההעתקים המותקנים, ואז אימות. ‏`--check` עונה *האם הכול במקום* בלי לשנות דבר |
| `ci.py` | **"האם השכפול הזה תקין?"** כל מה שלא דורש התקנה — השער שמולו נמדד push, והדבר היחיד שמריץ את מסלול השכפול הטרי |
| `close.py` | **"מה הסשן הזה השאיר פתוח, בכל מקום?"** שורה אחת לכל מקום, ו‑`--commit` סוגר כל אחד במונחים שלו |
| `sync_project_settings.py` | כותב את `.claude/settings.json` של כל repo רשום מתוך ה‑`tracks` שברישום, ואת העוגנים אל ההגדרות של המכונה |
| `verify_guards.py` | שער המעקות: כל צינור, ועוד השוואת בתים של כל העתק מותקן מול ה‑repo הזה |
| `check_references.py` | כל נתיב שהרשומות האלה מצביעות עליו — האם הוא עדיין קיים |
| `check_ownership.py` | כל סקיל מקומי מוצהר, וכל הצהרה עדיין מצביעה על משהו |
| `check_scripts.py` | הסקריפטים שסקיל מוסר לסשן: האם הם נפרסים, האם ה‑imports שלהם נפתרים. **סטטי בלבד — שום דבר לא מורץ** |
| `check_bilingual.py` | שני עותקי השפה של מסמך, והאם הם התרחקו זה מזה |
| `touched_report.py` | קורא את היומן: האם סשן באמת נוגע ביותר מ‑repo אחד, והאם הוא מגיע מעבר לרישום |

**איך סקיל מגיע אליהם.** ‏`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/grove.py <tool> …` —
הפלאגין יודע איפה הוא מותקן, והמתאם הזה יודע איך להגיע משם אל ה‑repo. הצורה המקבילה
`python3 $GROVE/tools/<tool>.py` היא אותה פקודה *ברגע ש‑`$GROVE` קיים*, ו‑`$GROVE` נכתב
בפריסה הראשונה — כך שדווקא הסקיל שתפקידו להריץ את הפריסה הראשונה לא יכול היה לנקוב בו.
הכלים נשארים כאן ואינם מועתקים לפלאגין, מאותה סיבה שהרישום כבר כפה: פלאגין הוא העתק נעוץ
בקומיט, וכלי שנשלח בתוכו הוא כלי של אתמול שפועל על repo של היום.

**ואחד מהם עלול להריץ משהו שלא אתה כתבת.** ‏`close.py --op <name>` קורא `places.json` של
סקיל, שעשוי להצהיר על פקודה שמדווחת את מצב המקומות שלו — וההצהרות נאספות מכל פלאגין
מותקן במכונה, מכל מרקטפלייס שאי פעם הוספת. שלנו רצות; של מישהו אחר מודפסת כדי שאדם יקרא
אותה, ו‑`--run-state` הוא המעשה המכוון. הרצת שורת shell מפני שקובץ ביקש היא צורתה של
מתקפת שרשרת אספקה, והיא תרוץ תחת ה‑shell שלך ועם המפתחות שלך.

## האינווריאנטה

> **קבצים של מקום ניתנים לכתיבה מבחוץ רק אם שום דבר שם אינו מצהיר שהם שלו.**

‏repo שנושא `.claude/skills` משלו יש לו בעלים *מקומיים* — סקילים שנטענים רק כשתיקיית
העבודה של הסשן היא ה‑repo הזה. כתיבה לשם מסשן חיצוני תמיד נראית כאילו הצליחה: הקובץ נוחת,
גיט מקמט, שום דבר לא שוגה. היא פשוט עוקפת את הסקיל שזו הייתה עבודתו. הכישלון שקט, ולכן הוא
דורש מעקה ולא מוסכמה.

### והבעלות מוצהרת, לעולם לא מנוחשת

כל מקום כותב את מה שבבעלותו ב‑`.claude/owns.json` שלו, והמעקה קורא רק את זה:

```json
{
  "claims": [
    {"paths": ["src/pages/", "src/data/apps.ts"], "owner": "add-app-to-site",
     "action": "block", "why": "the page structure is written by this skill"},
    {"paths": ["content/en.json"], "action": "warn",
     "why": "edit the JSON, run `npm run content`, commit both together"}
  ]
}
```

**שתי פעולות, והן אינן חוגה.** ‏`block` הוא לנתיב שסקיל מקומי *מחבר* — קריאת סקיל מבחוץ
אינה תחליף להרצתו, ולכן כתיבה שם באמת מדלגת על משהו. ‏`warn` הוא לנתיב שנושא **כלל** ולא
בעלים: הכתיבה עשויה להיות לגיטימית לחלוטין, היא רק חייבת לדעת משהו קודם.

**מה שלא הוצהר — פתוח.** קודמו חסם repo שלם כדי להגן על שלושה תת‑עצים, ונזקק לשתי רשימות
חריגים ברישום כדי להישאר שמיש; שתיהן נמחקו ב‑2026-09-10. לזה אין מה לתחזק ואין חריגים
לשמור מסונכרנים. המחיר הוא שמקום שאינו מצהיר דבר מוגן בכלום — וזו ברירת המחדל הכנה, וזו
הסיבה שקיימות בדיקות הסחיפה שלמטה.

## ‏registry.json

**שלושה דברים כאן שייכים ל‑grove, והשאר שייך למישהו אחר.** הוא קורא את `projects` (איפה
כל repo, ואילו מסלולים הוא טוען), את `ignored` (repos שהושארו בחוץ במכוון, כדי שההצעה לא
תחזור) ואת `keys_root` — עוגן, משום שסקיל שזקוק לסודות חייב יכולת לנקוב בתיקייה שקיימת
במכונה הזו בלי לדעת איך קוראים לה. כל השאר בקובץ שייך למרקטפלייס ששם אותו שם: ל‑repo יש
זהות אחת, ופיצולה לשני רישומים הוא הדרך שבה שתי תשובות מתרחקות זו מזו. מדור ה‑`apps`
בתבנית הנשלחת הוא בדיוק זה, ועץ שאינו שולח דבר צריך למחוק אותו.

איפה כל פרויקט, אילו מסלולים הוא טוען, ו — דרך שמות הרשומות שלו — מה משמעות כל משתנה עוגן
על המכונה הזו. זהו מידע של המכונה: ה‑repo שולח את `registry.example.json`, ו‑`deploy.py`
מעתיק אותו בשכפול טרי.

**המעקות קוראים את שתי הרשימות.** ‏`projects` ו‑`apps` הן שתי רשימות של repos שנבדלות רק
במפתח שנוקב בנתיב (`root` / `repo`), ושלושה מעקות קראו פעם רק את `projects` — כך שה‑repos
של האפליקציות, אלה שסשן שחרור צפוי לכתוב אליהם מבחוץ יותר מכול, ישבו מחוץ לכל גבול. כולם
עוברים היום דרך `grove_repo.registry_roots()`, כך ששתי הרשימות לא יוכלו להתרחק שוב.

## המעקות — שבעה, והם מגיעים עם הפלאגין

הם נשלחים בתוך `grove`. ‏`plugins/grove/hooks/hooks.json` רושם אותם, כך שהתקנת הפלאגין היא
מה שמניח אותם על מכונה: אין צעד התקנה משלנו ואין רשומה ב‑`~/.claude/settings.json`. ‏grove
הוא הפלאגין שתמיד פועל, וזה בדיוק הטווח שהם צריכים — מעקה שמגן על repo אחד מפני סשן של
repo אחר חייב להיטען בסשן האחר.

| קובץ | אירוע · מסנן | מסרב / מדווח |
|---|---|---|
| `honor_ownership.py` | `PreToolUse` · `Write\|Edit\|MultiEdit\|NotebookEdit\|Bash` | כתיבה לנתיב שמקום אחר הצהיר עליו כשלו |
| `scope_foreign_commits.py` | `PreToolUse` · `Bash` | `commit -a` / `add .` / `push` המכוונים ל‑repo שהסשן אינו עומד בו — ומחזיר את הסטטוס של אותו repo כשהוא מאשר |
| `record_touched_repos.py` | `PreToolUse` · רוב הכלים | רושם בלבד: באילו repos הסשן נגע, ומה הוא כתב |
| `warn_uncommitted_roots.py` | `Stop` | עבודה שהסשן הזה השאיר ללא קומיט ב‑repo רשום |
| `warn_stale_plugin_cache.py` | `Stop` | ה‑repo וההעתקים המותקנים של הפלאגין התפצלו |
| `warn_ownership_drift.py` | `Stop` | סקיל מקומי שאיש אינו מצהיר עליו, או הצהרה ששרדה את מה שתיארה |
| `offer_registration.py` | `UserPromptSubmit` | ה‑repo הזה אינו באף רשימה ברישום, ולכן שום מסלול לא נטען כאן |

**הם נכשלים בבטחה, בשתי דרכים שונות.** מעקות ה‑`PreToolUse` נכשלים *פתוח* — כל שגיאה, מטען
פגום או רישום חסר מאשרים את הפעולה, כי מעקה שבור לעולם אסור לו לעצור את העבודה. הוקי ה‑`Stop`
וה‑`UserPromptSubmit` נכשלים *בשקט*: אין להם מה להתיר, ואחד שזורק שגיאה בכל תור גרוע מאין.

‏`offer_registration` יושב על `UserPromptSubmit` ולא על `SessionStart` שאליו הוא כמובן שייך,
כי **אפליקציית הדסקטופ אינה מציגה פלט של הוק SessionStart כלל** — הוא רץ שם נכון שלושה
סבבים והגיע למודל ולתמליל, אך מעולם לא למסך.

**הרישום אינו נוסע איתם.** הוא מידע חי, שנכתב מחדש בכל פעם שנרשם repo, כך שהעתק נעוץ
בקומיט האחרון שהותקן היה עונה על שאלה של אתמול. ‏`grove_repo.py` מגשר בין השניים: ‏`GROVE_ROOT`,
אחר כך הליכה כלפי מעלה מהקובץ, ואז ה‑`installLocation` של המרקטפלייס עצמו — וזה מה שעונה
מתוך המטמון.

### מה המעקות אינם רואים

נאמר כאן ולא מכוסה בנייר, כי מעקה שמתחזה לכיסוי מלא גרוע ממעקה שגבולו ידוע:

* **מה שסקריפט כותב מבפנים** — `python3 build.py` יכול לכתוב לכל מקום, ושום דבר בשורת
  הפקודה לא מעיד על כך;
* **יעד שמחושב** — `git -C $DIR push`, נתיב שנבנה ב‑`$(…)`: הוא מתפענח ב‑shell, בזמן ריצה,
  והמעקה רואה משתנה;
* **מחרוזת פקודה שהוא אינו יודע לפענח בוודאות** — ולכן הוא מאשר אותה.

## השער: הרץ אותו לפני שאתה מקמט מעקה

‏`install.py` היה השער פעם, כי ההתקנה הייתה הרגע שבו מעקה נכנס לתוקף. הרגע הזה הוא היום
`claude plugin install/update`, שה‑repo הזה אינו הבעלים שלו — ולכן השער עבר למקום שבו
נעשה השינוי:

```bash
python3 tools/verify_guards.py
```

הוא מריץ כל צינור, אומר איזה העתק באמת רץ והאם הוא תואם ל‑HEAD, ומדווח על רישומים שנותרו
מעידן הרישום הידני (`--clean` מסיר בדיוק אותם). אפשר גם להריץ כל צינור לבדו:

```bash
python3 plugins/grove/hooks/scripts/tests/test_scope_foreign_commits.py
```

או להפעיל מעקה ביד — פלט פירושו סירוב, וה‑JSON נושא את הנימוק; אין פלט פירושו אישור:

```bash
echo '{"cwd":"/some/other/place","tool_input":{"file_path":"<a path some place declared it owns>"}}' \
  | python3 plugins/grove/hooks/scripts/honor_ownership.py
```

למה כל מעקה קיים, ומה נפסל בדרך — [`docs/cross-repo-session/`](../docs/cross-repo-session).
